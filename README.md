# Sign PDF

Sign a PDF in your browser. No account, no upload, no paywall, no watermark.

**Open PDF → Add signature → Place it → Download signed PDF**

A static site you can host for free on GitHub Pages. Everything runs in the
browser tab: the PDF and your signature are never sent anywhere.

## Features

- Open a PDF by drag-and-drop or file picker. Clear errors for non-PDFs, damaged files, and password-protected or encrypted files, shown *before* you sign anything.
- Multi-page preview with page navigation and zoom. Pages render lazily, so long documents stay fast.
- Create a signature by **drawing** (mouse, finger, or stylus), **typing** your name in one of three bundled script fonts, or **uploading** a PNG/JPEG (with optional white-background removal). Blank signatures are rejected.
- Place signatures on any page. Move, resize proportionally, duplicate, and delete them. Works with touch, and has keyboard alternatives: arrows move, Shift+arrows move faster, `+`/`-` resize, `D` duplicates, `Delete` removes.
- Downloads `<original-name>-signed.pdf`. The original file is unchanged, and all pages, text, vectors, links and form fields are kept. Each signature is embedded as a transparent, high-resolution image in the page content.
- Warns if the PDF appears to already carry a certificate-based digital signature.
- **Start over** clears the document and signature without reloading. Opening another PDF never silently discards placements you haven't downloaded.
- Works offline once loaded.

## Privacy guarantees (and how they're enforced)

- **No backend.** The site is static files. There is no server code to receive anything.
- **No third-party requests.** PDF.js, its worker and data files (CMaps, standard fonts, wasm decoders), and the signature fonts are all bundled and served from the site itself. There are no CDNs, analytics, trackers or external fonts.
- **Content-Security-Policy.** The production build ships `connect-src 'self'` and `default-src 'self'`, so the page cannot send data to any other origin even by accident.
- **Nothing persisted.** Documents and signatures live only in memory (JavaScript variables and `blob:` URLs). The app doesn't use localStorage, sessionStorage, IndexedDB, cookies, or a service worker. *Start over* or closing the tab clears them.
- **Tested.** The end-to-end suite loads the app, goes offline, then opens, signs and exports a PDF. It asserts that every request was a plain `GET` for a static file under the site's own path, that none carried a body, and that localStorage, sessionStorage, cookies, IndexedDB, Cache Storage and service workers are all empty.

The host (GitHub Pages) sees normal page-load requests, like any website, but never your files.

## What this is not

This places a **visible** signature image on the page, the electronic equivalent of signing a printout. It does **not** create a certificate-based digital signature (PAdES/PKCS#7), verify identity, or keep an audit trail. Whether a visible signature is acceptable is up to the recipient. Nothing here is legal advice.

## Local development

Requires Node.js 20.19+ (tested with Node 26).

```bash
npm ci                 # install exact, locked dependencies
npm run dev            # dev server at http://localhost:5173/
npm run build          # type-check + production build into dist/
npm run preview        # serve dist/ at http://localhost:4317/sign-pdf/ (GitHub Pages-style subpath)
```

`npm run dev` and `npm run build` first copy the PDF.js worker and data files
into `public/pdfjs/` (and third-party licenses into `public/licenses/`). Both
folders are generated and git-ignored.

## Tests

```bash
npx playwright install chromium webkit   # once
npm test               # unit tests, then build, then end-to-end tests
npm run test:unit      # Vitest only
npm run test:e2e       # builds, then runs Playwright against dist/ served under /sign-pdf/
```

All fixtures are generated by code in `tests/fixtures/fixtures.ts`. There are no private documents.

**Unit tests (Vitest)** cover:
- The display ↔ PDF coordinate conversion for 0/90/180/270° pages, crop boxes with non-zero or negative origins, and `/UserUnit`, compared against PDF.js's own viewport transform at several zoom levels.
- Clamping, proportional resize, and zoom independence.
- Export: signatures are placed on every page of the rotated, mixed-size and "tricky" fixtures. PDF.js then parses the *exported* file, and the test computes where each image is actually painted from the operator list. It must match the editor's rectangle to within 0.001 pt. Text must still be extractable.
- Detection of digital-signature dictionaries and encrypted files.

**End-to-end tests (Playwright)** run against the production build served under a `/sign-pdf/` subpath. Every request outside that path returns 404, as on a GitHub Pages project site. They cover:
- Draw, type and upload; placing on several pages; keyboard move/resize; duplicate; delete.
- Rotated pages (0/90/180/270), cropped, negative-origin, dirty-CTM and UserUnit pages, and a mixed-size document. Each download is re-rendered with PDF.js in a separate, isolated browser context, and the signature pixels are located on the rendered page. They must match the placement to within 1.5 pt.
- Zoom in/out/fit and window resizing don't move signatures.
- Errors (not a PDF, corrupted, password-protected), the digital-signature warning, blank-signature rejection, and confirmation before discarding work.
- Lazy rendering of a 60-page PDF.
- Offline signing and export with no data sent and nothing stored.
- On a phone (Pixel 7 emulation with real CDP touch input): swiping scrolls the document, drawing on the pad doesn't scroll, and dragging a signature with a finger moves it.
- A cross-browser smoke test on WebKit (desktop Safari and iPhone emulation).

## Deploying to GitHub Pages

The build uses relative asset URLs, so it works at `https://<user>.github.io/<any-repo-name>/` without configuration.

1. Create a GitHub repository (e.g. `sign-pdf`) and push this project to its `main` branch.
2. In the repository, open **Settings → Pages** and set **Source** to **GitHub Actions**.
3. The workflow in `.github/workflows/pages.yml` runs the tests, builds, and deploys on every push to `main`. You can also start it by hand from the **Actions** tab.
4. The site is published at `https://<user>.github.io/<repo-name>/`.

## Known limitations

- **Encrypted or password-protected PDFs** can't be saved. The app says so when you open one. Save an unprotected copy in another PDF app first.
- **Existing digital signatures are invalidated.** The output is a fully rewritten file (pdf-lib doesn't do incremental updates), so certificate signatures, incremental-save history and PDF/A conformance claims are not preserved. The app warns when it finds a signature dictionary, but that check may miss unusual files.
- **XFA (LiveCycle) forms** may not display correctly. The app warns when it detects one.
- The signature is an image in the page content, not a form field or annotation.
- Very large PDFs are limited by device memory. Both the original bytes and the PDF.js copy are held in memory.
- **Offline rendering:** a few PDF features load extra data files on first use (CJK fonts without embedded glyphs, JPEG 2000 and JBIG2 images). If you go offline before such a file is first opened, PDF.js falls back to approximate fonts, and such images may not show *in the preview*. The exported PDF is unaffected because it reuses the original file's content.
- Needs a current browser (ES2022, `<dialog>`, module workers). The automated tests run on Chromium and WebKit (Safari's engine); Firefox has not been tested automatically.

## Project layout

```
index.html              page markup (start screen, workspace, dialogs, FAQ)
src/geometry.ts         the one coordinate model shared by editor and exporter
src/pdf.ts              PDF.js setup and document opening/validation
src/inspect.ts          pre-flight export check, digital-signature/XFA detection
src/export.ts           builds the signed PDF with pdf-lib
src/viewer.ts           lazy page rendering, zoom, navigation
src/placements.ts       drag/resize/keyboard placement layer
src/signature.ts        draw/type/import → trimmed high-res PNG
src/main.ts             app state and UI wiring
scripts/                PDF.js asset copy, subpath static server
tests/unit, tests/e2e   Vitest and Playwright suites
tests/fixtures          fixture generators
```
